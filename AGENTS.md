# Project preferences

- Keep the app compact and native. Include `retro_trans.__version__` in the main window title, including test builds.
- Warn users patching PS3 games to remove the related old installation data before playing. Clearly distinguish installation data from saved games; never remove it automatically.
- Ask before unpacking a CHD. Keep the completed ISO/BIN in a new child folder beside the CHD and select that extracted file, so patching does not unpack the source again. Scanning must not silently unpack CHDs.
- Do not create or publish a release after routine changes. Release creation, publishing, and pushing require the user's explicit request; local builds and tests are fine.
- The user restored small-download original-PKG Automatic: accept the original PKG and its matching local work.bin/.rif, download component patches/extras, decrypt and rebuild locally, and verify through isolated native installation before saving. This supersedes the prior CPK-only direction. Keep manual installed CPK patching and generic hardware rePatch. Never revive package-size whole-PKG xdelta downloads or bundle/download licenses.
- Private PKG/hardware downloads may use existing GitHub CLI sign-in; credentials stay in memory, are sent only to the GitHub API and stripped from cross-host redirects. Private CPK releases can be downloaded manually and applied through Apply xdelta. Do not claim that a private release is automatically in the public binary catalog.
- Retry transient Windows sharing locks for Vita file verification and owned workspace cleanup. Cleanup must preserve an earlier verification/conversion/cancellation exception, never operate outside the current generated workspace and never terminate a user's existing emulator.
- Hardware rePatch should discover the game by its original PKG and release profile when Local patch is blank. Retain legacy Z3 compatibility. Asset-only profiles preserve the executable and omit authentication replacement; bounded added credits/font attribution are hash-verified. Installation needs the matching game's work.bin, never a license from another title.
- Automatic identifies original Vita PKGs by lightweight header checks, requests the matching local license, discovers VITA-PKG.json and its small component ZIP on Patch, then creates a verified translated PKG. Keep the Vita tab for local ZIP overrides and hardware rePatch; retain ordinary binary/CPK routes. Licenses are cleared when input changes; originals and user emulator data/saves stay untouched.

- The user explicitly requested publishing tools 0.5.16 after the small-download PKG and generic rePatch validation. This authorizes its source push and Windows release. Keep older withdrawn whole-PKG builds withdrawn and retain historical proof records. Future builds still require explicit release permission.
