# Retro Trans 0.4.1

Apply several required xdelta files as one complete patch solution. This
supports releases such as Marionette Handler 2, which needs both Track 3 and
Track 17 patched together.

## Using multi-file solutions

- In **Automatic**, choose **Folder…**, or browse to a required track or its
  CUE/GDI. The release must declare its required files in a v2 manifest.
- The app identifies each component by its exact size and hash, handles renamed
  inputs and mixed versions, and selects a target reachable by the complete set.
- **Route details** lists every component and its patch sequence. Latest, Next
  version only, and specific targets remain available.
- All patched files and declared unchanged tracks/descriptors are verified and
  saved together in a new folder. Existing destinations are refused and
  originals are preserved. Cancellation or failure removes incomplete output.
- Missing or duplicate components block patching; long missing-file lists stay
  in the scrollable details area so the main window remains compact.

Use unpacked tracks for multi-file discs. Multi-track/GD-ROM CHD extraction and
recompression are not included. Single-file releases, supported CHDs, manual
xdelta application, and Z3 save conversion continue to work.

## For patch maintainers

The release builder and catalog support manifest v2 with explicit `solutions`,
component output names, and hashes/sizes for unchanged files. Original and
translated game binaries remain local. Existing v1 releases remain supported;
multiple xdelta assets are not automatically assumed to form a group.

See [the release standard](https://github.com/retro-trans/retro-trans-tools/blob/v0.4.1/docs/RELEASE_STANDARD.md)
and [multi-file configuration example](https://github.com/retro-trans/retro-trans-tools/blob/v0.4.1/examples/multi-file-release-config.json).
Users must update to 0.4.1 or later before consuming v2 game manifests.
Marionette Handler 2's existing 0.1.17 catalog entry still has v1 metadata;
automatic grouping becomes available when its game release supplies the new
solution metadata. This app release does not rewrite that game's release.

## Downloads and validation

- **Retro-Trans.exe:** standalone Windows x64 application; no Python installation
  is required.
- **Retro-Trans-Windows.zip:** the same EXE with README and third-party notices.
- **UPDATE.json:** the size and SHA-256 used by the automatic updater.

Existing installations download verified updates at startup and install them
on the next launch, preserving settings and caches. The bundled catalog includes
the latest verified repository records available at build time.

Tests cover multi-file recognition, direct/chained routes, unchanged components,
corrupt inputs, cancellation, output preservation, catalog import, and compact
UI layout at different display scales. A local test using Marionette Handler 2
0.1.17's actual two patches verified all 17 resulting tracks and the original
CUE, then recognized the resulting set as 0.1.17. This verifies file output;
in-game playtesting is separate.
