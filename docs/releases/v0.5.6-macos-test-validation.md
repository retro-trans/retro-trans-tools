## HTTPS regression

The 0.5.5 ZIP contains no CA PEM/certifi package. Its online smoke check used
the host Python interpreter, which masked dependence on build-machine roots.
The user's screenshot does not expose the underlying exception, so the exact
failure on that machine remains inferred, not remotely observed.

0.5.6 bundles pinned certifi 2026.7.22, its MPL-2.0 license and 121 CA roots.
Mac GitHub requests use an explicit verified SSL context, with required peer
verification and hostname checks. Missing/damaged bundle fails closed. TLS,
certificate, DNS and timeout messages are distinguished without raw URLs or
secrets. Windows retains its existing OS certificate handling.

Both **frozen executables**, not host Python, pass `--network-check` with
SSL_CERT_FILE and SSL_CERT_DIR pointing to absent fixture paths. Each report
records default CA count 0, bundled count 121, required verification and hostname
checks enabled. Each downloads and validates:

- The public catalog, containing 88 patch edges.
- The registered Vita profile and complete ZIP with all 153 delta files.
- The official architecture-specific Vita3K DMG, including publisher byte size
  and SHA-256 verification through GitHub's actual asset redirects.

The existing offline startup, native xdelta/CHD round-trip, four-tab UI,
whole-app replacement, preserved previous bundle, actual next-launch updater
and official Vita3K CLI-startup checks also pass on each Mac. No game PKG,
work.bin, auth dump, keys or saves were sent to CI.

## Limits

  not Developer ID signed/notarized; approve via Privacy & Security as needed,
  never disable Gatekeeper.
- Actual game PKG/work.bin conversion on Mac and physical-Vita gameplay remain
  unverified. Reports retain `real_game_pkg_tested: false`. The affected user
  must retry Create rePatch with 0.5.6; network tests do not prove decryption.
- Existing experimental MX limitations remain. No user game/license inputs are
  included in any published artifact.
